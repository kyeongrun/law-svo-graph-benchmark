# 법령 SVO 그래프 비교

동일한 법령 원문과 동일한 엔티티·릴레이션 스키마를 사용해, 두 SVO 추출 방식으로 구축한 그래프를 비교하는 실험 저장소입니다.

- **방식 A**: KoNLPy 형태소 분석 결과와 결정 규칙을 이용한 SVO 추출
- **방식 B**: LLM이 문장 단위로 직접 반환하는 구조화된 SVO 추출

두 방식은 동일한 문장 단위, 스키마 검증 규칙, 엔티티 정규화 규칙, 그래프 DB 스키마, 평가셋을 공유해야 합니다. 비교 대상은 스키마가 아니라 **SVO 추출 방식이 만들어 내는 그래프의 품질**입니다.

## 현재 상태

이 커밋은 의도적으로 **골격만** 포함합니다. 추출 로직, LLM 호출, KoNLPy 의존성, 데이터 복사, DB DDL, Docker 설정은 아직 추가하지 않았습니다.

## 기본 원칙

- 그래프에는 주어·술어·목적어와 원문 위치만 저장한다.
- 기간, 금액, 수치, 조건 등 법령 상세 내용은 그래프 속성으로 저장하지 않는다.
- 상세 내용은 `source_ref`로 원문을 다시 찾아 확인한다.
- 두 방식의 결과는 같은 입력/출력 계약을 통과한 뒤 서로 다른 적재 공간에 저장한다.

예: `정보보호 책임자는 6개월 이내에 xx로 보고해야 한다.`

```text
(정보보호 책임자)-[:보고하다]->(xx)
```

`6개월` 및 원문 전체는 그래프에 복사하지 않고, 해당 문장의 위치만 관계에 연결한다.

## 다음 설계 순서

1. 기존 프로젝트의 엔티티·릴레이션 스키마를 이 저장소의 v1 계약으로 동결한다.
2. `source_ref`의 정확한 형식(법령/조문/항/문장/문자 오프셋)을 정한다.
3. 공통 문장 분할 및 정규화 책임 범위를 정한다.
4. 두 추출기의 공통 입출력 형식과 제외 규칙을 정한다.
5. 평가셋과 비교 지표를 정한 뒤 구현을 시작한다.

자세한 역할 분리는 [docs/repository-layout.md](docs/repository-layout.md), 현재 열어둘 설계 쟁점은 [docs/design-questions.md](docs/design-questions.md)에 정리되어 있습니다.
